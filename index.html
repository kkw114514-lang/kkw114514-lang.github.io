About

关于我

我是王跃凯，金融数学背景（南方科技大学本科，香港城市大学硕士在读），正在向游戏策划方向转型，主攻数值策划 / 系统策划。金融建模训练让我习惯用假设、数据和验证闭环处理复杂问题，这与游戏数值设计的「设计—测试—复盘—调优」高度一致。

作为重度卡牌玩家，我长期关注构筑选择、数值平衡与风险收益博弈。目前正独立开发《Winterfort》，把 Excel 设计表、规则文档、C# 战斗内核、自动检查和 Godot 调试场景整合成同一条可验证的制作流程。

数值 / 数据

精通 Excel 数据建模与平衡测算，了解 Python / MATLAB 基础；可独立完成数值配置、资源核算与平衡迭代。

系统 / 文档

擅长游戏系统拆解与策划文档撰写，能把复杂机制结构化、清晰表达；具备系统化设计思维。

引擎 / 工具

使用 Godot 4.7.1、C# 与 .NET 8 开发主工程，保留 GDScript 原型经验；能使用代码与生成式 AI 工具加速验证和内容生产。

玩家视角

全品类深度涉猎，卡牌见长：宝可梦官方道馆杯冠军、杀戮尖塔 A10、炉石传说传说段位。

Winterfort

PvE 卡牌构筑 Roguelike · 主策划 / 独立开发 · Godot 4.7.1 / C# / .NET 8
509自动检查点
65C# 卡牌类
23第一层普通怪
13现行设计表
  • 围绕契约师与精灵构建单人 PvE 战斗：玩家是唯一行动主体，精灵提供常驻被动与专属卡；五种属性表达玩法方向，并可组合双属性路线。
  • 建立现行数值标尺、卡面语言、五系与双系卡池、角色与精灵、遗物道具及第一层敌人设计，并明确区分定稿、评审稿和待裁提案。
  • 完成确定性随机、牌堆、事件与 Hook、伤害与状态、出牌、回合、敌人和内容模型等 C# 战斗内核；24 组、509 个无头检查点已全部通过。
  • Godot C# 调试战斗场景已完成编译、资源导入与启动检查；当前正在把旧版完整 UI 原型接回新版内核，首个切片锁定“王女 × 炎舞”。
  • 世界观以冻灾、回拨、钟与锚定者为核心，王室、教廷、求终者和魔法学院构成主要势力；提案内容不会自动升格为正史。

当前开发仓库保持私有；项目演示、设计样例与阶段性构建可在沟通时提供。
